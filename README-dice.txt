## 3. 投掷是怎么做的（核心）

**一句话：点一下 → 先离线跑一遍完整的刚体物理，拿到逐帧轨迹 → 按真实时间回放。**

### 3.1 为什么不能再用动画曲线
旧实现是「先算一个目标四元数，再让骰子逐面绕共享边翻 41.8°，最后 slerp 到位」。
它有三个死结，怎么调都救不回来：

1. 旋转轴只取了方向、穿过**球心**，所以是「原地自转」而不是「绕桌沿的棱翻滚」
2. 姿态是插值出来的，与重力、接触、摩擦**无关**，所以没有加速/减速/回弹
3. 起手要先「摆正当前顶面」、收尾再「对齐结果面」——这就是你看到的那次强制转动

### 3.2 现在的数据流

```
点击 throwDice()
   └─ prepareThrow()                     ← 把当前姿态丢给 planThrow
        └─ planThrow()                   ← 定点投掷（核心）
             ① 在「安全圈」里挑一个绝对落点（穿过桌面中心到另一侧，半径 0.55~0.95×安全半径）
             ② 由「起点 → 落点」定出手方向，反推一个初始水平速度
             ③ simulateThrow() 预演一遍，得到实际停稳位置
             ④ 没落在目标附近？按「实际位移 / 期望位移」比例修正初速，重跑（最多 6 次，通常 2~3 次收敛）
        └─ 返回 { 轨迹(每步的位置+四元数), 撞击时刻表, 停稳后的顶面 }
   └─ startTrack()                       ← 开始回放
tick() 每帧：playT += 真实帧间隔 → sampleTrack(playT) 线性插值位置 + slerp 姿态
   └─ playT ≥ duration → finishTrack()：直接读模拟结果的顶面点数
```

**关键点：回放只是「播放录像」，不参与物理；结果在读停稳姿态时就已经定死了，
没有任何事后补转、对齐、纠正。**

### 3.2.1 为什么一定要「定点投掷」

如果只给「出手方向 + 速度」，骰子会原地起跳、原地落下——因为飞行只有 0.7 秒，
横向速度一小就等于站在原地转，看着很假。但横向速度一调大，落点又不受控，
连续投掷会一步步漂出画面。

所以改成反过来做：**先决定落在哪，再反推初速**。而且落点必须用**绝对坐标**
（在安全圈内取点），不能用「朝某方向扔多远」——实测后者会因为每次都有方向抖动，
稳定地漂到圈外（p90 落点半径 1.5，安全圈只有 1.2）。

### 3.3 物理模型（`dice-physics.js`）

| 项 | 实现 |
|---|---|
| 形状 | 12 顶点 / 20 三角面的正二十面体（外接球半径 1，内切半径 0.79465） |
| 碰撞 | 12 个顶点 vs 无限平面 `y=0`，穿透的顶点生成接触点 |
| 求解 | 顺序冲量法：法向冲量（累积钳制 ≥0）+ 库仑摩擦（切向单方向约束，`|Jt| ≤ μJn`）+ 竖直位置补偿 |
| 积分 | 半隐式欧拉，固定 `dt = 1/240`；四元数用 `q += ½ωq·dt` 再归一化 |
| 惯量 | 正多面体关于中心是各向同性张量，所以用标量 `I = 0.30·mR²` |
| 地面接触 | 只有真穿透才算接触；稳态穿透由 `slop = 1.5‰` 兜住（视觉 1.5 mm 以内） |
| 停稳 | 至少 **3 个支点** + 线速度 < 0.055 + 角速度 < 1.0，持续 0.13 s → 冻结 |
| 结果 | 停稳后 `法线·UP` 最大的那一面，直接取点数 |

实测一次模拟约 **0.5 ms**（600 步左右），点击瞬间跑完，无感。

### 3.4 四个「现实补丁」（很重要，删了就会露馅）

1. **休眠必须 ≥3 个支点**
   只靠速度阈值的话，骰子会停在一个顶点或一条棱上——数学上那是另一个平衡点，现实里不可能。
   要求 3 个支点等于要求「真的有一个面贴桌」。
2. **teeter 补偿（顶点上打转）**
   只有 1~2 个支点、又慢吞吞耗了 0.28 s，说明它卡在「顶点上像陀螺一样转」。
   处理：先把角速度乘 0.30（卸掉陀螺感），再加一记随机小力矩把它推倒；0.45 s 冷却，防止反复踢。
   —— 真实的桌面有噪声/不平整，一瞬间就倒了；这是对它建模，不是作弊。
3. **定点投掷（见 3.2.1）**
   先选落点再反推初速 + 闭环校准，保证既「飞得远」又「落得回来」。
4. **落点半径自适应视口**
   `safeRadius()` 在桌面上限 1.45（够横跨桌面），竖屏手机自动收到 ~1.1。
   `planThrow` 的落点半径取 `0.55~0.95 × 安全半径`，起点越靠外这一掷走得越远。

## 4. 参数表（想继续调，改这里）

物理参数在 `dice-physics.js` → `simulateThrow()` 的 `opt` 默认值：

| 参数 | 当前值 | 作用 / 调大调小的效果 |
|---|---|---|
| `dt` | 1/240 | 模拟步长。调小更稳但更慢，一般别动 |
| `gravity` | **20** | 重力。**调小 = 整体变慢、翻滚更从容**（当前比真实世界慢约 4 倍，慢动作观感） |
| `restitution` | 0.50 | 恢复系数。调大弹得更欢（金属骰子砸硬桌会弹两三下），调小像砸在软垫上 |
| `friction` | 0.46 | 摩擦。调大更容易「咬住」地面翻滚、不容易滑走 |
| `inertia` | 0.30 | 转动惯量（标量）。调大转得更木、调小转得更轻 |
| `contactDamp` | 1.6 | 接触时的滚动阻力。调大收得更快 |
| `slop` / `correction` | 1.5e-3 / 0.75 | 允许穿透 & 位置补偿比例，影响停稳时的抖动 |
| `sleepLin` / `sleepAng` / `sleepTime` | 0.055 / 1.0 / 0.13 | 休眠阈值（只允许 3 支点时睡） |
| `sleepMinContacts` | 3 | **别调到 3 以下**，否则会出现「立在棱上」 |
| `maxTime` | 5.0 | 兜底上限，正常投掷 3.1 s 内一定停 |
| `softStop` | 2.4 | 超过这个时间加大阻尼，只耗能量不改方向 |

投掷初值在 `createThrow()`：

| 参数 | 当前值 | 作用 |
|---|---|---|
| `hSpeed` | 由 `planThrow` 迭代决定（≈0.2~2.5） | 水平出手速度，不是手调的，是校准出来的 |
| `lift` | 5.15 ~ 7.15 | 竖直出手速度 → 决定抛高/滞空时间 |
| `spin` | 8.4 ~ 16.2 | 初始自旋（rad/s）→ 决定空中翻几圈、落地后还滚几下 |
| `tilt` | ±0.4 | 自旋轴歪斜，避免每次翻滚轨迹一模一样 |

定点投掷在 `planThrow()`：

| 参数 | 当前值 | 作用 |
|---|---|---|
| 落点半径 | `0.55~0.95 × safe` | 想让它飞得更远，把这个调到 `0.75~1.05`（配合下面 safe 上限） |
| 方向抖动 | ±26° | 免得每次都从桌子正中穿过 |
| `attempts` / `tolerance` | 6 / 0.35 | 校准次数与允许的落点误差 |
| `safeRadius` 上限 | 1.45（`index.html`） | **想整体加大行程就调它**；越大骰子停得越靠画面边缘 |

取景 / 力度自适应在 `index.html`：
`frameCamera()`（距离 `camR`）、`viewHalfWidth()`（把视口四角投到桌面算安全半径）、
`throwPower()`（窄屏降抛高与自旋）、`safeRadius()`（落点校验圈）。

## 5. 当前实测数据（`node _dev/sim-test.mjs`，400 次连续投掷）

| 指标 | 桌面（safe 1.45） | 竖屏（power 0.7 / safe 1.15） |
|---|---|---|
| 时长 中位 / 90% / 99% | **1.97 / 2.33 / 3.04 s** | 1.86 / 2.27 / 2.79 s |
| 每掷真实位移 中位 / 90% | **2.07 / 2.63**（≈1 个骰子直径） | 1.70 / 2.18 |
| 空中水平位移 中位 / 90% | **1.29 / 1.89** | 0.99 / 1.45 |
| 可见翻滚（角速度 >1.5 或速度 >0.5 的最后时刻） | 中位 1.73 s | — |
| 自然停稳 | **100%**（从没靠超时硬停） | 100% |
| 停稳后顶面与 UP 的夹角 | 0°（`topDot = 1.000`，真的有一个面贴桌） | 0° |
| 停止时最低顶点离地误差 | −1.5 mm ~ 0 mm | 同 |
| 点数分布 | 1—20 均匀（每面约 5%） | 同 |
| 单次模拟 / 单次点击的定点校准 | ≈ 0.5 ms / ≈ 1.9 ms（2~3 次预演） | — |

（400 次里的极值会抖：最长 3.4~3.8 s，落点偶尔到 2.3，属于尾部噪声，不影响观感。）

> 「空中水平位移 1.29」= 骰子直径的 0.65 倍，肉眼是明确的「扔出去」而不是原地转。
> 想再大就调 `safeRadius` 上限（见 4）。

## 6. 本地预览（必须走 HTTP）

**不能直接双击 `index.html`**：页面用 `<script type="module">`，`file://` 下 origin 是 `null`，
浏览器会以 CORS 拒绝加载 `dice-physics.js` 和 `vendor/three/*.js`，结果就是只有背景、没有骰子。
（原版也是同样结构，双击一样白屏；线上正常是因为部署在 GitHub Pages，走 http。）

```bash
cd dice-source
python -m http.server 8080      # 然后打开 http://127.0.0.1:8080/index.html
# 或者：npx serve .
```

## 7. 调试

控制台 `window.__dice`：

```js
__dice.phase    // idle | intro | roll | settle | win
__dice.pose     // { p:[x,y,z], q:[x,y,z,w] } 当前姿态
__dice.sim      // 本次模拟的完整结果：轨迹、撞击时刻表、停稳姿态、点数
__dice.paused   // = true 可定格回放
__dice.playT    // 定格时手动跳到某一时刻
__dice.throw()  // 投一次
```

旧版的 `window.__lastRoll` / `window.__finalDot` 保留。

### 自动化截图务必用显卡
无头 Chromium 默认会退回 SwiftShader 软件渲染，这个页面每帧要渲 2048² 软阴影，
软件渲染会**吃满一个核**（一帧 250 ms）。带上下面两个参数就会走真显卡
（实测 `ANGLE (NVIDIA ... D3D11)`，整轮截图从 120 秒降到 8 秒）：

```
--headless=new --use-angle=d3d11 --ignore-gpu-blocklist --enable-gpu
```

`__dice.paused = true` 后可以定格任意帧再截图，用来检查翻滚姿态。

## 8. 已知取舍 / 待定

- **掷出 20 的概率仍然是 1/20**（和改造前一模一样，本次只动动画）。
  想让门禁能过，用「预演挑选」：在 `prepareThrow()` 里循环采样初值，直到预演的顶面
  就是 20 再播放——观感完全一样（依然是纯物理），因为重试对用户不可见；
  平均约 20 次重试 × 0.5 ms ≈ 10 ms，代价可忽略。**默认没开**，因为它会改变「掷骰子」的含义。
- 骰子在极少数情况下会先落到顶点上再被 teeter 补偿推倒，肉眼是「歪一下然后倒平」，属于可接受范围。
- 物理只处理了桌面（无限平面），没有墙/其他骰子；要加多颗骰子需要扩展成刚体间碰撞。
